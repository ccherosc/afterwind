# Afterwind Game Dev Skill

## Purpose

Use this skill when working on the Afterwind / Skywriter browser game in Claude Code.

The goal is to build a lightweight, reliable, browser-based 2D airplane action game with minimal errors, conservative token usage, and no use of large-context or 1M-context tools.

## Absolute Rules

1. Never invoke, enable, request, or depend on any 1M context tool.
2. Never use large-context expansion unless the user explicitly overrides this skill.
3. Keep responses concise and implementation-focused.
4. Prefer editing the smallest relevant files instead of reading the whole project.
5. Do not scan the full repository unless required.
6. Do not summarize large files unless directly needed.
7. Do not rewrite working systems without a clear reason.
8. Avoid speculative architecture changes.
9. Always preserve the current playable state unless fixing a broken state.

## Project Context

This is a browser-based 2D arcade airplane game.

Working title:
Afterwind

Original concept:
The player controls a small airplane. The player’s flight path is recorded during each round. At the end of the round, that path is analyzed and converted into weather zones for the next round.

Core mechanic:
Fly today. Change tomorrow’s sky.

The game should feel casual, fast, readable, and addictive.

## Core Systems

### Player

The player should have:

* x
* y
* rotation
* speed
* throttle
* integrity
* altitude
* boost state

Movement should be arcade-style, not simulation-heavy.

### Path Recording

Record lightweight path points at a controlled interval, not every frame.

Recommended:

```js
const PATH_SAMPLE_MS = 100;
```

Each path point should include:

```js
{
  x,
  y,
  heading,
  speed,
  altitude,
  time
}
```

Do not store unnecessary data.

### Weather Generation

After each round, analyze the recorded path and generate weather zones.

Basic mapping:

* Wide circular movement creates Thermals.
* Tight repeated circular movement creates Storms.
* Long straight movement creates Jetstreams.
* Rapid direction changes create Turbulence.
* Multiple self-crossings create Lightning Knots later if requested.

### Weather Effects

Weather zones should be readable and simple.

Thermal:

* Helpful
* Increases altitude
* Adds score multiplier

Storm:

* Dangerous
* Damages integrity

Jetstream:

* Pushes plane in a direction
* Adds speed bonus

Turbulence:

* Disrupts steering
* Slightly reduces control

## Performance Rules

1. Use requestAnimationFrame.
2. Avoid expensive per-frame allocations.
3. Limit particles.
4. Limit weather zone count.
5. Cap path history.
6. Use simple collision checks first.
7. Avoid pixel-perfect collision.
8. Use object pools only if performance becomes a problem.
9. Keep mobile performance in mind.

Recommended caps:

```js
const MAX_PATH_POINTS = 800;
const MAX_WEATHER_ZONES = 20;
const MAX_PARTICLES = 150;
const MAX_ORBS = 8;
```

Required:

* Touch controls
* Large buttons
* No tiny UI
* No required keyboard-only actions

Desktop controls:

* A/D or left/right arrows turn
* W/S or up/down arrows adjust throttle
* Space boosts

Mobile controls:

* Left turn button
* Right turn button
* Throttle up
* Throttle down
* Boost button

## Visual Direction

Use a bright sky background with clean arcade readability.

Use Kenney sprites where helpful, but do not overcomplicate animation.

Recommended visuals:

* Plane sprite rotates toward heading
* Trail is a translucent line
* Orbs glow
* Thermals are soft green circles
* Storms are dark purple pulsing circles
* Jetstreams are blue lanes/arrows
* Turbulence is orange wavy motion

Gameplay readability is more important than visual detail.

## Round Structure

The game loop should follow:

```text
Splash
Start Day
Player flies
Record path
Collect orbs
Timer reaches zero
Analyze path
Generate weather forecast
Next Day starts with new weather
Repeat until crash
Game Over
```
